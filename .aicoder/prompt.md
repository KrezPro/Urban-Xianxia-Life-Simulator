## ОПИСАНИЕ ПРОЕКТА

**Название:** Urban Xianxia Life Simulator (BitCultivator)
**Жанр:** Симулятор жизни / Текстовая RPG / Урбан-культивация / Idle (референсы: BitLife, Immortal Taoists)
**Платформа:** Android / iOS (Touch Input, строго вертикальная ориентация)
**Движок / Стек:** React Native, Expo, TypeScript, Zustand, react-native-mmkv.

**Суть игры:**

* Игрок балансирует между двумя мирами. Днем он школьник/офисный клерк, зарабатывающий доллары, а ночью — тайный культиватор, поглощающий энергию Ци, очищающий меридианы и сражающийся с городскими демонами. Жизненный путь идет от обычного смертного до бессмертного, пока игрок не погибнет от старости, конкурентов или удара Небесной Скорби.

Ключевые механики:

1. **Возрастной цикл:** Игрок нажимает «Повзрослеть (+1 год)». Генерируются случайные текстовые события, требующие выбора (мирские и тайные). Применяются изменения статов.
2. **Показатели (Stats):** Мирские (интеллект, здоровье, привлекательность, деньги) и тайные (Ци, духовный корень, карма, стадия культивации).
3. **Прорыв (Breakthrough):** При накоплении шкалы Ци игрок пытается прорваться на новую стадию. Шанс зависит от статов и пилюль. Провал может привести к смерти.
4. **Реинкарнация (Престиж):** Смерть не конец. Душа перерождается, конвертируя достижения прошлой жизни в Карму для покупки перманентных баффов в новой жизни.

**Технические требования (обязательные правила архитектуры):**

1. **Управление состоянием:** Только через `Zustand`. Запрещено использовать Redux или Context API для глобальных, часто меняющихся данных. Состояние дробится на логические сторы (PlayerStore, LogStore, InventoryStore).
2. **Персистентность (Сохранения):** Только синхронное хранилище `react-native-mmkv`. Категорически запрещено использовать `AsyncStorage`, так как оно блокирует UI при загрузке огромных массивов логов. Использовать паттерн проверки гидратации (hasHydrated).
3. **UI и Рендеринг:** Функциональные компоненты (FC) и хуки. Для рендеринга больших списков (особенно Журнала событий, где могут быть тысячи записей) использовать ТОЛЬКО `FlashList` (от Shopify), обычный `FlatList` не применять для логов.
4. **Вычисления и Idle-логика:** Для характеристик Ци на поздних этапах (триллионы/квадриллионы) обязательно использовать тип `BigInt` для избежания переполнения. Фоновые расчеты делать через дельту времени (сверку `Date.now()` при старте), а не через фоновые процессы телефона.
5. **Data Driven:** Все события, предметы и шансы хранятся в отдельных `.json` или `.ts` константах в папке `data/`.
6. **Локализация (i18n)**: В проекте поддерживается мультиязычность. Запрещен хардкод текста в .tsx файлах. Любой новый игровой контент, диалоги интерфейса и события должны описываться логическими ключами в коде, а физические строки генерироваться в соответствующих .json словарях в Game/src/locales/{lang}/. Для западного рынка (EN) китайская терминология должна адаптироваться (например, "Qi Deviation" -> "Mana Burn").
