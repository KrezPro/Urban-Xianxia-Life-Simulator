# ВЫУЧЕННЫЕ УРОКИ (DataForAI)
1. Hermes: таблицы GameConstants читать ТОЛЬКО через tableNumber(table, key, fallback) — защита от "Cannot convert undefined value to object".
2. navigation.navigate('Log') ЗАПРЕЩЁН: журнал открывается только модалом LogScreen с onClose из LifeScreen.
3. NotificationToast: таймер автоскрытия запускается от момента монтирования, а не от createdAt, иначе тосты исчезают мгновенно.
4. generateYearEvent в useYearlyCycle обёрнут в try/catch с buildFallbackEvent(): год не должен крашить приложение.
5. Адаптивность вкладки Мир: пороги подбираются по реальным окнам устройств (800-844pt); скролл во вкладке Мир ЗАПРЕЩЁН.
6. commit_message должен быть XML-безопасным: без символов &, <, > и без переносов, ломающих CDATA/теги.
7. Центровка hero-блока: бейдж аватара центрируется по всей ширине (heroTopRow justifyContent center), блок возраста — position absolute справа.
8. Адаптивный дизайн вкладки Мир: единый scale = clamp(windowHeight / 800, 0.75, 1.35), хелпер sw(v) = Math.round(v * scale); карточка статов flex: 1 без мёртвых полос.
9. DraggableGrowButton — абсолютный перетаскиваемый overlay: НЕ резервирует вертикальное место (paddingBottom равен боковым отступам).
10. Нативные модули (expo-av, expo-file-system) НЕЛЬЗЯ импортировать статически в аудио-слое: статический import крашит старый dev-клиент на загрузке бандла ("Cannot find native module 'ExponentAV'").
11. В тесте (__DEV__ === true: expo start / dev-клиент / Expo Go) аудио НЕ инициализируется вовсе; в release APK/AAB (__DEV__ === false) звук и музыка работают.
12. Звуки вызывать ТОЛЬКО через standalone-функции с optional call: playUiPress?.(), playTab?.(), playToggle?.(). Никогда через навигацию по объекту (AudioManager.xxx) — иначе TypeError "Cannot read property 'playUiPress' of undefined".
13. WAV-звуки и фоновой loop генерируются процедурно (proceduralAudio.ts) и кэшируются в FileSystem как base64 WAV: без бинарных ассетов и без copyrighted-файлов.
14. useSettingsStore (soundEnabled/musicEnabled) персистится в MMKV с hasHydrated; App гидратирует его до запуска и вызывает initAudio?.() после готовности всех сторов.
15. Metro TransformError "SyntaxError" с lineNumber 0 = битый/невалидный JSON-файл в графе импортов (JSON.parse падает без номера строки). Лечится перезаписью JSON начисто.
16. Metro резолвит ВСЕ статические require на этапе сборки: если JS-пакет отсутствует в node_modules, бандл падает TransformError до рантайма. После правки package.json ОБЯЗАТЕЛЕН npm install в папке Game.
17. Metro bundler НЕ ПОДДЕРЖИВАЕТ динамический require(переменная): "Invalid call at line N: require(moduleId)". Аргумент require обязан быть литеральной строкой.
18. Правильный паттерн optional native-модуля: literal require('expo-av') ВНУТРИ try/catch (в функции инициализации, не на верхнем уровне модуля). Metro статически включает пакет в бандл, рантайм-ошибка отсутствия нативки ловится, аудио деградирует в тишину; в бинарах с нативкой (release APK/AAB, Expo Go) модуль загружается и звук работает.
19. react-native-iap и react-native-google-mobile-ads версий до RN 0.79 используют устаревший API (currentActivity, runOnUiThread в базовом классе). В RN 0.79+ (Expo SDK 53+) эти методы удалены — ошибка "Unresolved reference 'currentActivity'" в Kotlin-компиляции. Лечение: обновить пакеты до совместимых версий (react-native-google-mobile-ads >= 15.0, react-native-iap >= 14.0).
20. babel-preset-expo должен совпадать с версией Expo SDK: для SDK 54 правильная версия ~54.0.10, а не 12.x или 14.x. Проверяется через expo doctor.
21. react-native-mmkv v4 работает через react-native-nitro-modules: если nitro отсутствует в package.json ЗАКОММИЧЕННОМ/загруженном в EAS, нативка MMKV не собирается, new MMKV() бросает, и приложение тихо уходит в memory-fallback (сохранения живут до закрытия приложения). Лечение: nitro 0.35.10 в package.json + self-test probe-ключом в mmkvStorage.ts + диагностика getStorageBackend() в SettingsScreen.
22. EAS Build архивирует ЛОКАЛЬНУЮ рабочую папку (не remote git), но только файлы вне .gitignore/.easignore; package-lock.json должен быть закоммичен и синхронен с package.json, иначе серверные npm install получат другой набор зависимостей.
23. Android 15+ принудительно edge-to-edge для targetSdk 35+: без android.edgeToEdgeEnabled в app.json Expo добавляет opt-out, и приложение выглядит "окном под статус-баром" (чёрные полосы, время/батарея отдельно от игры). Лечение: edgeToEdgeEnabled true + StatusBar hidden (expo-status-bar) + SafeAreaView только из react-native-safe-area-context (встроенный SafeAreaView из react-native НЕ даёт insets на Android).
24. Если сохранения/звук "не работают" в release, но краша нет — добавлять видимую диагностику (Settings -> Diagnostics: storage backend, audio initialized/available, dev mode), а не гадать по тихим try/catch.
