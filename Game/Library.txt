# АРХИТЕКТУРНАЯ БИБЛИОТЕКА ПРОЕКТА
1. Стейт-менеджмент: только Zustand. Сторы: Player, Event, Inventory, Locale, Social, Notification, Techniques, Lifestyle, Settings.
2. Хранилище: только синхронное, через zustandStorage. Паттерн hasHydrated обязателен. AsyncStorage ЗАПРЕЩЁН.
3. Списки: FlashList для журнала и потенциально больших рейтингов. FlatList для логов не использовать.
4. Типизация: strict TypeScript, интерфейсы в src/types/index.ts.
5. Большие числа: хранить как string, считать через safeBigInt.
6. UI: функциональные компоненты. Текст только из locales/{lang}/*.json.
7. Баланс и контент: data/*.json.
8. Навигация: route names только английские: Life, Dao, Activities, Store, Settings. Маршрута Log НЕТ. Sect отключён.
9. Социальный слой: offline-first секты, локальные инвайты, локальный рейтинг. Код сохранён, но вкладка Sect отключена.
10. Рейтинги: score как string, сортировка через BigInt.
11. Локализация: useLocaleStore хранит ru/en, дефолт en; смена языка выполняется только в SettingsScreen.
12. Offline-симуляция секты ограничена SOCIAL_MAX_OFFLINE_SECONDS.
13. ТРЁХУРОВНЕВОЕ синхронное хранилище (mmkvStorage.ts): 1) react-native-mmkv с probe-тестом (основное по архитектуре); 2) expo-kv-store с probe-тестом (страховка под SDK 54/RN 0.81 bridgeless, где Nitro/MMKV-рантайм может быть несовместим); 3) memory-fallback только аварийно. getStorageDebugInfo() отдаёт backend + цепочку ошибок + env-отпечаток в Settings -> Diagnostics.
14. Theme.ts: единая темная тема для всего UI.
15. components/ui/index.tsx: единый UI-кит. Использовать Button, Card, ProgressBar, StatRow, DetailsModal вместо ручных стилей.
16. utils/helpers.ts: единый модуль для formatLargeNumber, BigInt-утилит, bps-утилит и random-утилит.
17. Если экран импортирует helpers или UI-кит, эти файлы должны существовать до запуска сборки.
18. Новые файлы всегда получать короткое описание в структуре проекта.
19. Кнопки должны поддерживать варианты primary, secondary, danger, gold, ghost, small, disabled, icon и onLongPress.
20. ProgressBar должен безопасно принимать progress от 0 до 1 и сам обрезать выходящие значения.
21. Вкладка Sect отключена в пользовательской навигации. Код секты остаётся в проекте как deprecated.
22. SectScreen больше не используется в TabNavigator, но файл сохранён для возможного будущего удаления.
23. SafeAreaView использовать только из react-native-safe-area-context, SafeAreaProvider оборачивает App.
24. StatRow поддерживает onPress и onLongPress для показа подсказок по long-press.
25. NotificationHost размещается глобально в App.tsx поверх NavigationContainer, использует absolute positioning с safe-area insets.
26. Подсказки хранятся в ui.json под ключом hints для каждого стата/фокуса.
27. Журнал открывается ТОЛЬКО модально из LifeScreen (LogScreen с onClose). navigation.navigate('Log') ЗАПРЕЩЁН.
28. DraggableGrowButton — перетаскиваемая кнопка взросления. Короткое нажатие вызывает growOlder, перетаскивание выполняется PanResponder в пределах LifeScreen.
29. IconButton добавлен в UI-кит для компактных кнопок без текста.
30. Draggable FAB имеет zIndex 900, NotificationHost остается выше с zIndex 1000.
31. LifeScreen использует обычный View вместо ScrollView; DraggableGrowButton остается абсолютным overlay. ScrollView во вкладке Мир ЗАПРЕЩЁН.
32. Здоровье игрока разделено на health (текущее) и maxHealth (максимальное). Во вкладке Мир в списке характеристик отображается maxHealth.
33. Техники Дао хранятся в useTechniquesStore как levels: Record<string, number> и сбрасываются при реинкарнации.
34. Активности образа жизни хранятся в useLifestyleStore как selected: LifestyleSelection и сбрасываются при реинкарнации.
35. Годовой цикл рассчитывается в useYearlyCycle и использует processLifestyleYear из utils/gameplayUtils.ts.
36. Карма-баффы стали многоуровневыми: quantity в useInventoryStore означает текущий уровень баффа.
37. Локализация дополнительных вкладок, техник, магазина и активностей вынесена в locales/{lang}/extras.json; локализация экрана настроек — в locales/{lang}/settings.json.
38. Все проценты в игре хранятся как basis points (bps): 1% = 100 bps, 100% = 10000 bps.
39. Стадии культивации имеют maxAge и softAge. Смертный не может жить бесконечно: после maxAge применяется шанс смерти от старости.
40. useYearlyCycle обрабатывает: survival cost, подписки, доход, здоровье, Ци, порталы, события, старение и отключение неоплаченных активностей.
41. При реинкарнации техники и lifestyle сбрасываются, карма-баффы сохраняются с уровнями.
42. gameplayUtils.ts содержит все математические расчёты годового цикла, техник, карма-баффов, старения и порталов.
43. DaoScreen использует закреплённый нижний блок прорыва, чтобы кнопка прорыва всегда была видна.
44. TabNavigator содержит 5 видимых вкладок: Life, Dao, Activities, Store, Settings.
45. eventGenerator.ts читает таблицы GameConstants ТОЛЬКО через tableNumber(table, key, fallback) — защита от Hermes "Cannot convert undefined value to object".
46. generateYearEvent в useYearlyCycle обёрнут в try/catch с buildFallbackEvent(), год не крашит приложение.
47. NotificationToast запускает таймер автоскрытия от момента монтирования, а не от createdAt.
48. useNotificationStore имеет pushGeneratedEventNotification и очередь NOTIFICATION_MAX_QUEUE=3, NOTIFICATION_MAX_VISIBLE=1.
49. Уроки по крашам и навигации записаны в Game/DataForAI.txt.
50. Пропущенные уведомления считаются в useNotificationStore.missedCount: если новое уведомление приходит при уже занятом видимом слоте, счётчик растёт. Кнопка сброса badge находится в LifeScreen на кнопке журнала (badge поверх иконки журнала).
51. Body Tempering стоит Ци и деньги: moneyCost = qiCost * GameConstants.BODY_TEMPERING.COST_MONEY_MULTIPLIER. Если множитель отсутствует или некорректен, использовать fallback 2.
52. Покупки в магазине Кармы идут по цепочке StoreScreen -> player.deductKarma -> inventory.addItem. quantity всегда нормализуется как целое число >= 0.
53. Причина смерти хранится в player.lastDeathCause, отображается в LifeScreen и передаётся в уведомлении death_reason.
54. DetailsModal из components/ui/index.tsx используется для показа деталей по long-press в DaoScreen и StoreScreen.
55. Числовые эффекты техник, карма-баффов, стадий и закалки тела показываются в деталях по long-press, а не в постоянном интерфейсе.
56. Портальные награды показываются в ActivitiesScreen только если соответствующее значение существует и больше нуля: деньги/Ци диапазоны, breakthroughBlessingBps, attemptCost, failDamage/failDamageBps.
57. processLifestyleYear возвращает portalBlessingGainedBps; при успехе портала portalQi добавляется к qiDelta, portalMoney добавляется к moneyDelta.
58. useYearlyCycle применяет report.portalBlessingGainedBps через player.addPortalBlessing и пишет лог extras.logs.portal_blessing_gained.
59. DaoScreen показывает активное благословение портала только при player.portalBlessingBps > 0. Благословение накапливается до PORTAL_BLESSING_CAP_BPS и списывается useBreakthrough после реальной попытки прорыва.
60. LifeAvatar строится только на встроенном Animated API (import { Animated } from 'react-native') и emoji, без графических ассетов и без react-native-reanimated. Все анимации используют useNativeDriver: true.
61. Возрастные группы LifeAvatar синхронизированы с порогами eventGenerator.ts: child меньше 12, teen меньше 18, adult меньше 50, mature меньше 80, elder от 80. Функция getAvatarAgeGroup экспортируется из LifeAvatar.tsx.
62. LifeAvatar — круглый бейдж с числовым пропом size и четырёхслойной дифференциацией стадий, чтобы игрок не путался: (1) эмодзи матрицей "возраст x тир" (Смертный/Ци/Основание/Ядро/Бессмертный); (2) цвет ауры по ТОЧНОЙ стадии (9 оттенков: qi1 #38BDF8, qi2 #22D3EE, qi3 #2DD4BF, f1 #A855F7, f2 #C084FC, f3 #E879F9, core #FBBF24, immortal #F8FAFF; смертный без ауры); (3) число пульсирующих колец ауры равно тиру (1-4, фазовый сдвиг 250мс); (4) число частиц Ци равно 2 + stageIndex (кап 6). Под бейджем — локализованное имя стадии (проп stageLabel через stageUtils.getStageName). Движения: crawl (младенец-смертный), breathe (tier 0-1), levitate (tier 2+ и elder).
63. Hero-карточка вкладки Мир: бейдж LifeAvatar центрируется по всей ширине карточки (heroTopRow justifyContent center), блок возраста закреплён position absolute справа и не сбивает центровку. В карточке статов есть строка «Расходы в год»: getSurvivalCost(age, stage) + сумма getLifestyleAnnualCost выбранных активностей (BigInt); формат "$0" при нуле и "-$X" при ненуле; long-press открывает подсказку hints.expenses с разбивкой по стоимости жизни и образу жизни.
64. Адаптивный дизайн вкладки Мир (автозаполнение и автомасштаб, без скролла и без ручных тиров): единый коэффициент scale = clamp(windowHeight / 800, 0.75, 1.35), хелпер sw(v) = Math.round(v * scale); все paddings/margins/шрифты/высоты баров/чипы фокуса вычисляются через sw(). LifeAvatar size = clamp(sw(76), 54, 96), шрифт возраста = clamp(sw(32), 24, 40). Карточка статов получает flex: 1 и съедает свободную высоту экрана; каждая StatRow обёрнута в View с flex: 1 и justifyContent center для равномерного распределения строк (мёртвых полос нет). StatRow принимает проп scale (дефолт 1) и масштабирует бейдж/иконку/шрифты/padding — другие экраны не меняются; проп dense сохранён для совместимости. paddingBottom контента равен боковым отступам (sw(16)): DraggableGrowButton — перетаскиваемый абсолютный overlay и НЕ резервирует место в вертикальной компоновке.
65. Вкладка Settings: SettingsScreen с выбором языка и тумблерами «Звук интерфейса» и «Музыка»; тексты в locales/{lang}/settings.json; плюс техническая карточка Diagnostics (storage backend/errors, env, audio).
66. useSettingsStore: soundEnabled/musicEnabled (дефолт true), persist в sync-хранилище, hasHydrated; App гидратирует его вместе с остальными сторами.
67. AudioManager экспортирует standalone-функции playUiPress/playTab/playSuccess/playError/playToggle/initAudio/disposeAudio/syncMusic плюс default-объект для совместимости; все вызовы в UI только через optional call (playUiPress?.()).
68. Аудио-политика: в тесте (__DEV__ === true) звук и музыка не инициализируются; в release APK/AAB работают. WAV генерируются процедурно и кэшируются в FileSystem.
69. Metro-гигиена: статические require резолвятся на этапе сборки (try/catch не спасает от отсутствия JS-пакета в node_modules — после правки package.json обязателен npm install); битый JSON в импортах даёт TransformError SyntaxError lineNumber 0 — JSON-файлы писать начисто и валидно.
70. Озвучка: Button/IconButton/StatRow/DraggableGrowButton играют playUiPress автоматически; кастомные TouchableOpacity (журнал, возраст, фокус-чипы, стадии Дао, закрытие журнала, выбор языка в настройках) вызывают playUiPress?.() вручную; смена вкладок играет playTab?.(); тумблеры настроек играют playToggle?.().
71. Optional native-модули (expo-av, expo-file-system, expo-navigation-bar, expo-kv-store) подключаются ТОЛЬКО через guarded literal require внутри try/catch: Metro статически включает пакет в бандл, рантайм-ошибка ловится и деградирует; guarded require ТРЕБУЕТ наличия пакета в package.json/node_modules (ставится через npx expo install).
72. Смена языка находится только в SettingsScreen; язык по умолчанию en для новых установок, сохранённый ранее язык остаётся благодаря persist.
73. Автосохранение прогресса: все игровые сторы persist в sync-хранилище и сохраняются при каждом изменении состояния; отдельной кнопки выхода нет. useIdleProgress дополнительно обновляет lastLoginTime при старте, каждые 60 секунд и при смене AppState (active/background/inactive), чтобы offline-прогресс рассчитывался от последнего момента активности.
74. Config plugins (Game/plugins/*.js): кастомные Expo config plugins для настройки Android-сборки. withIapPlayFlavor.js инжектит missingDimensionStrategy 'store', 'play' в app/build.gradle для решения ambiguity-ошибки react-native-iap (amazon vs play flavors). Подключаются в app.json как относительные пути в массиве plugins.
75. EAS Build: использует ТОЛЬКО закоммиченные в git файлы. После правки app.json, package.json, plugins/ ОБЯЗАТЕЛЕН git add -A && git commit перед запуском eas build.
76. app.json плагины: expo-system-ui (backgroundColor для userInterfaceStyle: dark), react-native-google-mobile-ads (androidAppId/iosAppId), react-native-iap (config plugin), локальный ./plugins/withIapPlayFlavor.js.
77. Версионирование для Play Console: versionName поднимается вручную в app.json (сейчас 1.1.5); versionCode НЕ пишется в app.json — управляется EAS (appVersionSource: remote, autoIncrement в production).
78. Fullscreen-политика Android: StatusBar hidden (expo-status-bar) во всех ветках App.tsx + скрытие системной навигационной панели через expo-navigation-bar (setVisibilityAsync('hidden') + setBehaviorAsync('overlay-swipe') + прозрачный фон), повторное скрытие при AppState 'active'.
79. Музыка v2 (proceduralAudio.buildMusic): 8-секундный бесшовный loop — детюнированный синус-пад (Am -> F), мягкий бас-пульс, пентатоническая мелодия (ля-минор пентатоника) с эхом +0.25с, редкие верхние искорки, applyFade для шва. Громкость music loop 0.22 в AudioManager. UI-звуки (click/toggle/tab/success/error) зафиксированы как удачные и не меняются.
80. Тихие try/catch в production ЗАПРЕЩЕНЫ без сохранения текста ошибки: state.lastError/avError/fsError (AudioManager) и backendErrors + env-отпечаток (mmkvStorage) выводятся в Settings -> Diagnostics; любой скриншот сам объясняет среду и причину деградации.
